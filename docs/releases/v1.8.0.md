# KubeChan v1.8.0

KubeChan v1.8.0 expands the evidence-backed investigation graph from explicit topology into bounded application discovery and adds model commentary to graph nodes without weakening the evidence trust boundary.

## Highlights

- Root-driven discovery for Ingresses, Services, workloads, Pods, HPAs, EndpointSlices, ConfigMaps, Secrets, PVCs, and StorageClasses.
- Deterministic observed and inferred relationships with recorded scores, strengths, reasons, and traversal policy.
- Explicit missing-reference nodes for unresolved workload and storage dependencies.
- Fresh analysis requests no longer receive previous diagnosis text, preventing stale conclusions from anchoring a new evidence snapshot.
- Every model node insight is validated against exact graph, claim, and source IDs.
- Neutral node comments when persona is disabled and tsundere KubeChan comments when it is enabled.
- Larger viewport-clamped graph tooltips with relevance-specific KubeChan artwork, wrapped text, and safe technical metadata.
- Full-width graph workspace, internal graph scrolling, improved node spacing, forward storage relationships, and edge labels shown only on hover or keyboard focus.
- Incident context can be attached before the model explicitly asks for another resource.

## Graph policy defaults

| Setting | Default |
|---|---:|
| Observed traversal depth | 4 |
| Inferred hops | 1 |
| Nodes | 50 |
| Edges | 150 |
| Candidates per gap | 5 |
| Strong inference score | 100 |
| Possible inference score | 60 |

The effective policy and truncation state are stored in every graph v2 snapshot.

## Compatibility and upgrade notes

- Existing DiagnosticRuns remain immutable and continue to render through the compatibility path.
- A fresh DiagnosticRun is required to obtain graph schema v2 discovery fields and `nodeInsights`.
- Inferred edges are amber and dashed. They are deterministic investigation hints and must not be interpreted as observed Kubernetes topology.
- KubeChan remains advisory and does not mutate user workloads.
