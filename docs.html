Documentation / v1.8.0

Operate KubeChan.

A minimal path from Helm install to a running incident workspace, followed by the Kubernetes resources KubeChan uses to represent operational state.

Safety boundary. KubeChan may create and update its own CRDs, but diagnosis and remediation remain advisory. It does not mutate the workloads it investigates.

Get started

Quick start

This guide uses the published OCI Helm chart. You need a Kubernetes cluster, Helm 3, kubectl, a default StorageClass for the backend volume, and access to a supported analysis provider.

Install the chart

Helm installs the five services and the kubechan.io/v1alpha1 CRDs into the control namespace.

SHELL
$ helm upgrade --install kubechan \
  oci://ghcr.io/aryzhykau/kubechan \
  --version 1.8.0 \
  --namespace kubechan \
  --create-namespace

Wait for the control plane

Confirm the workloads are ready before opening the application.

SHELL
$ kubectl get pods -n kubechan
$ kubectl get crd | grep kubechan.io

Open the incident workspace

The default service is internal. Port-forward it for a first evaluation; use chart ingress values for a shared environment.

SHELL
$ kubectl port-forward -n kubechan \
  svc/kubechan-frontend-ui 8080:8080

Open http://localhost:8080. On first startup, retrieve the generated administrator password:

SHELL
$ kubectl get secret kubechan-admin-credentials \
  -n kubechan -o jsonpath='{.data.password}' | base64 -d

Configure analysis access

Sign in and open Settings → LLM Provider. Provider credentials and model selection are stored per user. On EKS, the chart also supports an IRSA role through llmGateway.irsa.roleArn.

Concepts

Operational model

KubeChan controllers turn detected symptoms into a small set of Kubernetes-native records. A ProblemCase captures one anomaly. Related cases are correlated into an Incident. Each requested investigation creates a new immutable DiagnosticRun.

ProblemCase→Incident→DiagnosticRun→Assessment

Exclusion rules control known noise before it becomes an active investigation. KubeChanState is internal shared presentation state, not an incident record.

API group kubechan.io

CRD reference

All five resources are namespace-scoped and served as kubechan.io/v1alpha1. The control-plane instances normally live in the Helm release namespace.

ProblemCase

problemcases.kubechan.io

A single detected anomaly tied to an affected Kubernetes resource. It is the atomic problem signal used for correlation and investigation.

Created by
cluster-watcher
States
open · investigating · resolved
Primary use
Detection record
  • spec.affectedResource — kind, namespace, name, and optional API group
  • spec.detector and spec.severity — why it was opened and its priority
  • spec.symptoms — observed detector symptoms
  • status.latestDiagnosticRunRef — most recent investigation snapshot

Incident

incidents.kubechan.io

Groups related ProblemCases around a workload root. Incidents may be detected automatically or reported manually in the UI.

Created by
correlator or backend
States
open · resolved
Primary use
Operator workspace
  • spec.rootResource — workload entry point for investigation
  • spec.problemCases — correlated problem references
  • spec.source and spec.userMessage — automatic or manual origin
  • spec.relatedResources — additional resources selected for context

DiagnosticRun

diagnosticruns.kubechan.io

A single evidence collection and analysis request. Completed runs are immutable snapshots; request a new run to collect current state.

Created by
backend-api
States
pending · running · completed · failed
Primary use
Immutable investigation
  • spec.incidentRef and spec.problemCaseRef — investigation context
  • status.evidenceRef — stored evidence snapshot
  • status.redactionSummary — sensitive-field handling metadata
  • status.analysisState and status.analysisResultRef — assessment lifecycle

KubechanExclusionRule

kubechanexclusionrules.kubechan.io

Suppresses selected detectors for matched resources, labels, namespaces, or recurring time windows. A model may propose a rule, but only a user confirms its creation.

Created by
operator through UI/API
Scope
namespace · resource · selector
Primary use
Noise control
  • spec.enabled and spec.description — lifecycle and intent
  • spec.detectors — detector names to suppress
  • spec.targetResources or spec.selector — match scope
  • spec.timeWindow — timezone-aware recurring periods

KubeChanState

kubechanstates.kubechan.io

A singleton named kubechan that shares UI persona state across services. It is operational presentation state, not evidence or diagnosis.

Created by
KubeChan control plane
Instance
one per control namespace
Primary use
Shared UI state
  • status.moodLevel — calm, irritated, or rage level
  • status.openIncidentCount — current open incident count
  • status.pokeCount and status.pokeExpiresAt — temporary UI interaction state

Operations

kubectl reference

Use the generated printer columns for a fast control-plane view. Detailed diagnosis belongs in the web workspace, where graph entities and citations can open their exact sources.

Active problemskubectl get problemcases -n kubechan
Open incidentskubectl get incidents -n kubechan
Investigation runskubectl get diagnosticruns -n kubechan
Noise controlskubectl get kubechanexclusionrules -n kubechan

Uninstall

Removing the Helm release removes KubeChan workloads. Helm does not delete installed CRDs automatically; review retained CRs before removing CRD definitions.

SHELL
$ helm uninstall kubechan -n kubechan
