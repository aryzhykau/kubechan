Architecture

How the services connect

Five services run inside your Kubernetes cluster. cluster-watcher detects anomalies and writes CRDs. diagnostics-worker collects evidence from the cluster. backend-api orchestrates everything — it's the central hub. llm-gateway calls the LLM. frontend-ui shows results in real time. Nothing ever writes to your workloads.

Kubernetes API watch / read
CRD creation / informer event
HTTP POST (evidence / analyze)
REST API + WebSocket
User interaction

Installation

Install with Helm

KubeChan ships as a Helm chart. All five services are deployed in a single release into the kubechan namespace. No shared LLM credentials are needed at deploy time — each user configures their own provider in the UI.

⚠️

Prerequisites: Kubernetes 1.28+, kubectl, Helm 3. Docker Desktop with Kubernetes enabled works for local testing.

1. Create namespace and apply CRDs

CRDs must be applied before the Helm release so the controllers can start cleanly.

bash
$ kubectl create namespace kubechan

# Apply all four CRDs
$ kubectl apply --server-side -f \
  https://raw.githubusercontent.com/aryzhykau/kubechan/main/helm/kubechan/crds/kubechan.io_incidents.yaml \
  https://raw.githubusercontent.com/aryzhykau/kubechan/main/helm/kubechan/crds/kubechan.io_problemcases.yaml \
  https://raw.githubusercontent.com/aryzhykau/kubechan/main/helm/kubechan/crds/kubechan.io_diagnosticruns.yaml \
  https://raw.githubusercontent.com/aryzhykau/kubechan/main/helm/kubechan/crds/kubechan.io_kubechanstates.yaml

2. Add Helm repo and install

bash
$ helm repo add kubechan https://aryzhykau.github.io/kubechan
$ helm repo update

$ helm install kubechan kubechan/kubechan \
  --namespace kubechan

# Verify all pods are running
$ kubectl get pods -n kubechan
NAME READY STATUS AGE
kubechan-backend-api-xxx 1/1 Running 40s
kubechan-cluster-watcher-xxx 1/1 Running 40s
kubechan-diagnostics-worker-xxx 1/1 Running 40s
kubechan-llm-gateway-xxx 1/1 Running 40s
kubechan-frontend-ui-xxx 1/1 Running 40s

3. Configure LLM provider

Open the UI, go to Settings → LLM Provider, choose AWS Bedrock or GitHub Copilot, enter your credentials, and save. No restart needed.

Common value overrides

my-values.yaml
# Detect problems faster (default debounce: 30s)
clusterWatcher:
  debounceWindowSecs: 10

# More log lines for verbose services
diagnosticsWorker:
  logTailLines: 1000
  prevLogTailLines: 500

# Expose via Ingress
frontendUi:
  ingress:
    enabled: true
    host: kubechan.example.com

# Larger DB volume (default: 5Gi)
backendApi:
  storage:
    pvc:
      size: 20Gi
bash
$ helm upgrade --install kubechan kubechan/kubechan \
  --namespace kubechan -f my-values.yaml
💡

Local development: Run make dev-up in the repo root. This uses Tilt with Docker Desktop Kubernetes and enables live-reload for all services. Requires Go 1.25+, Python 3.13+, uv, Tilt ≥ 0.33.
